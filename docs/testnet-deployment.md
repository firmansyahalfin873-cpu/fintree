# Deployment kontrak Base Sepolia

## Persiapan dengan ekstensi wallet (eksperimental)

Jalankan `npm run setup:testnet` di folder proyek, lalu buka alamat lokal yang ditampilkan di terminal pada browser yang memiliki ekstensi wallet. Tombol **Pilih Base Sepolia di wallet** meminta wallet memilih atau menambahkan jaringan uji; konfirmasi dilakukan di wallet dan tidak mengirim pembayaran. Hubungkan wallet uji; halaman akan mencoba menampilkan saldo ETH uji dan menyediakan tombol untuk memeriksanya kembali setelah faucet mengirim dana. Masukkan alamat treasury uji yang memang akan menerima biaya protokol, dan buat kata sandi baru untuk penyimpanan aplikasi. Treasury ditetapkan permanen pada kontrak; periksa kembali sebelum mengirim. Kata sandi ini bukan seed phrase atau kata sandi wallet dan tidak boleh dikirim ke chat. Parameter jaringan memakai chain ID 84532 dan RPC Base Sepolia sebagaimana dicantumkan pada [referensi jaringan Circle](https://github.com/circlefin/cctp-go/blob/main/chains.go).

Halaman menampilkan rincian persiapan dan meminta persetujuan transaksi melalui ekstensi wallet. Setelah kontrak dikonfirmasi, buka kembali penyimpanan menggunakan kata sandi tadi untuk memulai layanan lokal. Simpan salinan aman folder `.fintree-data/setup` beserta kata sandi secara terpisah: folder ini berisi signer dan kunci webhook terenkripsi serta catatan deployment. Kehilangan kata sandi atau file tersebut dapat membuat konfigurasi testnet tidak dapat dipulihkan. Jangan menghapus catatan transaksi untuk mencoba ulang bila hasil belum jelas.

Jika file signer atau rencana persiapan hilang sementara catatan terkait masih ada, proses persiapan berhenti dan meminta pemulihan. Pulihkan file yang cocok dari cadangan; aplikasi tidak membuat signer pengganti atau menyusun ulang rencana yang hilang secara otomatis. Mengganti signer akan membuatnya tidak cocok dengan kontrak yang telah dipasang.

Saat layanan pertama kali dimulai, identitas publik kunci enkripsi webhook diikat ke catatan deployment. Jika file kunci itu kemudian hilang atau tidak cocok, layanan berhenti dan memerlukan pemulihan dari cadangan. Untuk catatan lama yang belum memiliki identitas tersebut, aplikasi juga menolak membuat kunci baru jika database lama ada tetapi file kuncinya tidak ditemukan. Salinan cadangan tetap diperlukan; pemeriksaan ini tidak dapat memulihkan file atau kata sandi yang hilang.

Saat persiapan dibuka lagi sebelum ada transaksi, saldo dan estimasi unit gas diperbarui dari jaringan. Unit gas bukan nilai biaya total dalam ETH; periksa biaya yang ditampilkan wallet sebelum menyetujui. Jika transaksi sudah dicatat, estimasi yang ditampilkan berasal dari persiapan awal, dan catatannya tetap dapat dilihat saat koneksi terputus.

Alur halaman telah diuji dengan wallet dan blockchain simulasi. Ekstensi browser sungguhan, transaksi di Base Sepolia, dan webhook ke endpoint nyata belum diverifikasi. Jika transaksi terhenti dan hash belum tersimpan, halaman menyediakan pemeriksaan hash dari riwayat wallet. Layanan mencocokkan pengirim, jaringan, nonce, dan data kontrak terhadap catatan sebelum menyimpan hash dan memeriksa receipt; ini tidak mengirim transaksi baru. Jika transaksi tidak ditemukan atau tidak sesuai, catatan tetap dipertahankan. Jika wallet ditolak sebelum transaksi dikirim dan tidak ada hash, proses perlu diperiksa secara manual; jangan menghapus catatan atau mengirim ulang secara otomatis. Layanan ini khusus testnet dan hanya berjalan di komputer lokal selama proses persiapan tetap aktif.

## Script alternatif

Script ini hanya untuk jaringan uji Base Sepolia, bukan mainnet. Kontrak masih eksperimental dan belum diaudit. Script memakai USDC testnet Base Sepolia yang tercantum dalam [referensi Circle](https://docs-w3s-node-sdk.circle.com/variables/chains.BASE_SEPOLIA.html), dan memeriksa bahwa RPC melaporkan chain ID 84532 sesuai [dokumentasi Base](https://docs.base.org/base-chain/api-reference/ethereum-json-rpc-api/eth_chainId).

Sebelum digunakan, siapkan RPC HTTPS, akun deployer khusus testnet dengan saldo ETH uji, alamat treasury testnet, dan alamat penandatangan quote yang dikendalikan secara aman. Akun deployer dan penandatangan quote dapat berbeda. Jangan memasukkan seed phrase atau kunci pribadi ke chat, file proyek, atau sistem kontrol versi. Variabel yang diperlukan tercantum di `.env.example`; file tersebut hanya contoh dan tidak dibaca otomatis.

1. Set `FINTREE_RPC_URL`, `FINTREE_DEPLOYER_ADDRESS`, `FINTREE_TREASURY_ADDRESS`, dan `FINTREE_QUOTE_SIGNER_ADDRESS` pada lingkungan proses. Jalankan `npm run prepare:testnet` untuk pemeriksaan **read-only**. Hasil menampilkan alamat, versi compiler, hash sumber, hash data transaksi, estimasi gas eksekusi, dan saldo deployer. Estimasi gas bukan jaminan total biaya jaringan.
2. Untuk mengirim deployment testnet, sediakan juga `FINTREE_DEPLOYER_KEY` melalui sarana penyimpanan rahasia lokal yang aman, lalu jalankan `npm run deploy:testnet`. Jika `FINTREE_DEPLOYER_ADDRESS` disediakan, script memeriksa kesesuaiannya dengan kunci. Secara opsional, set `FINTREE_EXPECTED_DEPLOYMENT_HASH` ke hash dari langkah persiapan agar data deployment yang berubah ditolak.
3. Script mencadangkan catatan di `.fintree-data/base-sepolia-deployment.json` **sebelum** mengirim transaksi. Catatan berisi alamat prediksi, nonce, hash, status, dan setelah berhasil alamat kontrak serta nomor blok. Script menolak menimpa catatan yang sudah ada. Gunakan alamat kontrak dan nomor blok tersebut sebagai `FINTREE_CONTRACT` dan `FINTREE_START_BLOCK` untuk layanan testnet.

Jika proses terhenti atau hasil tidak pasti, periksa catatan, nonce, alamat prediksi dan transaksi di penjelajah Base Sepolia sebelum melakukan apa pun lagi. Status `reserved` dapat berarti transaksi belum dikirim atau hasilnya belum sempat dicatat; jangan menjalankan ulang dengan menghapus atau mengganti catatan secara otomatis. Kontrak hanya diverifikasi terhadap konfigurasi yang diharapkan setelah receipt berhasil; ini bukan audit keamanan atau verifikasi kode sumber di explorer.

Saat ini script telah diuji pada blockchain lokal, termasuk jalur kegagalan dan penolakan catatan duplikat. Belum ada deployment Base Sepolia yang dilakukan oleh proyek ini.
