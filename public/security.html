Fintree is still in development and has not been independently audited. The current implementation is limited to local and Base Sepolia testing; it is not ready for production funds.

PAYMENT VERIFICATION

A closer look at
the payment journey.

The payment monitor checks evidence against the stored request before the payment is marked complete.

01

Details are signed

The quote binds the invoice, token, merchant, amounts, deadline, chain and contract.

02

Evidence is checked

The service checks the transaction receipt and event against the expected payment details.

03

Confirmation is observed

A matching payment can remain in confirmation until the configured policy is met.

The current testnet policy and reorganization handling still require public-network verification and operational review.

FOR YOUR INTEGRATION

Keep credentials
where they belong.

API keys and webhook secrets are sensitive. The workspace shows newly issued secrets once so they can be stored on your server.

Read the developer guide ↗
01

Keep keys on your server

Never publish API keys in browser code, mobile apps, or shared repositories.

02

Verify webhook signatures

Check the signature against the exact request body and handle repeated events using their IDs.

03

Check before signing

Review the network, recipient, amount and gas in your wallet. Never enter a seed phrase on Fintree.
